# Development & Build Guide

### Prerequisites
* **Node.js**: 22.x (the version configured in GitHub Actions)
* **npm**: the version bundled with Node.js 22; npm is used for installation and scripts
* **Rust / Cargo** *(for Tauri Desktop target)*: with active toolchain
  * *Linux build packages:* `sudo apt-get install -y libwebkit2gtk-4.0-dev build-essential curl wget file libssl-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev`
* **Android Studio / SDK** *(for Android Capacitor target)*

### Project Architecture & Key Files

Understanding the file structure helps navigate and extend the application:

* **Entry Points & Core**:
  * `src/App.tsx`: Central application state (about 8,000 lines): tab lifecycle, query execution for DuckDB / ClickHouse, graph orchestration, hotkeys.
  * `src/main.tsx` & `src/index.css`: React entry point and Tailwind CSS v4 styling rules.
  * `server.ts`: Local Express server: proxy for native DuckDB, ClickHouse requests and VFS synchronization. `npm run dev` uses Vite middleware; with `NODE_ENV=production` the server serves the built `dist/` assets. It is not included in desktop or Android packages.
* **UI Components (`src/components/`)**:
  * `SqlEditor.tsx`: SQL editor built on CodeMirror 6 behind a stable interface (`SqlEditorRef`: `getSelection`, `replaceSelection`, `setSelectionRange`, `replaceRange`). Editor logic lives in `src/editor/` (`editorOps.ts` pure text operations, `sqlLanguage.ts`, `cmExtensions.ts`, `hotkeysMatch.ts`, `templates.ts`).
  * `DataStatsViewer.tsx`: Results data table, pagination, cell zoom, quick filters, column stats, and charts.
  * `SettingsModal.tsx`: Comprehensive configuration (DuckDB, ClickHouse, UI scaling, export presets, sync paths, hotkeys defaults `DEFAULT_HOTKEYS`).
  * `ActionMenuTabContent.tsx` & `SqlSnippetsManager.tsx`: Snippet library, quick actions, multi-statement `-- @job` pipelines.
  * `MarkdownPreview.tsx`: rendered Markdown document in the graph area (copy to Word, export to PNG/JPEG).
  * `CustomNodes.tsx` & `MermaidNodes.tsx`: Node and edge rendering for AST Lineage and Mermaid diagrams.
  * `WasmFileManagerModal.tsx`, `VersionHistoryModal.tsx`, `ClickhouseModal.tsx`, `VaultSettingsSection.tsx`, `ExcelSettingsTab.tsx`: file manager of the WASM virtual file system, snapshots with diff, connection form, vault, Excel presets.
  * `FileTreePanel.tsx`: file tree under the schema (search, sorting, context menu, move by drag and drop); the logic is in `utils/fileTree.ts` and `utils/fileTreeProviders.ts`.
* **Data Exploration (`src/analysis/`)**: `Explore.tsx` manages the Perspective lifecycle; `sdk.ts` loads the SDK lazily; `transport.ts` shares DuckDB connections; `viewSql.ts` / `replaySql.ts` capture replay scripts; `export*.ts` / `htmlReplay.ts` handle saving and HTML bootstrap. Viewer styles, common labels, date split paths and Split By metric ranges are scoped here.
* **Core Logic & Utilities (`src/utils/` & `src/lib/`)**:
  * Graph: `astToGraph.ts` (SQL parsing, CTE extraction, lineage, layout), `mermaidParse.ts` / `erParse.ts` (flowchart and erDiagram text → shared model) / `mermaidToGraph.ts` / `mermaidSvg.ts` / `edgePath.ts` (Mermaid), `graphExport.ts`, `canvasLimits.ts`.
  * Documents: `markdown.ts` (own Markdown renderer, no external library), `documentExport.ts`, `documentClipboard.ts`.
  * Excel: `excelExporter.ts` (report generation with `exceljs`, SQL directive parsing), `excelParse.ts`, `excelSettingsStorage.ts`.
  * Storage: `sessionStorage.ts`, `resultStorage.ts`, `schemaDbCache.ts`, `snippetsStorage.ts`, `versionHistory.ts`, `vaultStorage.ts` (AES-256 GCM), `appSession.ts`.
  * Layout: `useIsNarrow.ts` (narrow-screen detection, up to 767 px).
  * SQL helpers: `sqlFormat.ts`, `sqlHighlight.ts`, `filteredSql.ts`, `columnStats.ts`, `src/lib/sqlUtils.ts` (variables, statement splitting).
  * `src/utils/i18n.ts`: Localization dictionary (the key is the Russian text, `EN_DICT` holds English).
  * `src/lib/duckdbWasm.ts`: Browser-based DuckDB WebAssembly engine with Parquet/CSV/JSON VFS support.
  * `src/lib/clickhouse.ts`: ClickHouse HTTP protocol client with auth, cancellation, COPY commands and the URI parser.
* **Native Targets**:
  * `src-tauri/`: Rust desktop layer (`main.rs`: DuckDB connection and queries, ClickHouse requests and COPY streaming, cancellation, text file read/write; `analysis.rs`: Arrow IPC for the Virtual Server; `fstree.rs`: file tree commands — listing, rename, move, move to trash, show in file manager, open with).
  * `capacitor.config.json`: Mobile wrapper configuration for Android builds (the `android/` folder is generated by CI).
* **Tests (`tests/`)**: Unit tests run with Vitest (`npm test`): utilities, storage, parsing, graph layout and exports. Ordinary WASM result normalization uses Arrow stubs. Exploration additionally has node:test checks, SQL replay on real DuckDB-WASM, browser HTML/PNG export checks and targeted native Rust/Arrow IPC tests.

### Quality Assurance & Testing

* **TypeScript type check**:
  ```bash
  npm run lint
  ```

* **Run test suite**:
  ```bash
  npm test
  ```

* `npm run lint` runs `tsc --noEmit` for `src/**`; it is not a separate style linter and does not type-check `server.ts` or `tests/`. Rust tests can be run separately with `cargo test --manifest-path src-tauri/Cargo.toml` (requires the desktop build prerequisites).

* **Exploration**: `npm run test:analysis` runs node:test checks; `npm run test:analysis-sql` compares replay scripts with live DuckDB-WASM Views, including grouping, splits, expressions and significant whitespace. `Tests` runs both alongside Vitest. `Analysis native Arrow` (`.github/workflows/analysis-native.yml`) runs `cargo test --manifest-path src-tauri/Cargo.toml --no-default-features analysis::tests -- --nocapture` and `tests/analysisNativeArrow.mjs` to compare native IPC with WASM fixtures. `Analysis export compatibility` (`.github/workflows/analysis-export.yml`) checks export codecs/files, PyArrow decoding, Datagrid HTML restoration and chart PNGs in Playwright; UI styling, SQL dialogs and scrolling are outside that export run. This does not replace manual Tauri/Android checks of the interface and file saving; exploration acceptance on Android is not yet confirmed.

* **Perspective Preparation**: `npm run build:analysis-export` copies the lazy ZSTD-WASM asset and applies two idempotent, version-scoped patches for Perspective 5.8.0: `scripts/patch-perspective-duckdb.mjs` preserves SQL literal/identifier whitespace, and `scripts/patch-perspective-number-locale.mjs` selects the Lens number locale, passing its value into the chart worker. Unknown versions/templates fail preparation. The npm startup/build/analysis-test hooks run it; Vite also prepares the number locale on startup and excludes `column-format` from dependency prebundling. Restart the dev process after replacing sources. SDK updates require rechecking these patches, date split paths, metric ranges, HTML bootstrap and JS/Rust Arrow IPC compatibility.

* **Data Precision**: Check BIGINT/DECIMAL display precision when changing adapters or chart formatters; Arrow IPC compression must preserve schema and exact values.

* **HTML Export Scope**: `htmlReplay.ts` registers the embedded table by its saved name and awaits load/restore for the stock Datagrid document. An unknown SDK template fails explicitly. Standalone HTML requires internet for the CDN runtime, uses the opening environment's locale and is not a complete workspace archive. Complex layouts, DuckDB expressions and aggregates need restoration checks against the embedded Perspective engine. Chart HTML over `file://` is outside confirmed support; use PNG for charts. The renderer-locale regression runs the actual worker Blob in an isolated JS realm without GPU; browser CI remains responsible for rendering and PNG export.

* **Before a build**: `npm run lint`, `npm test`, `npm run build`.

### Coding Rules & Conventions

* **Localization (i18n)**: All user-facing strings must have corresponding keys in `src/utils/i18n.ts` for both Russian (`ru`) and English (`en`).
* **Security & Secrets**: Never hardcode connection strings or tokens. Use the encrypted `vaultStorage` or environment variables.
* **Styling**: Use Tailwind CSS utility classes for static styling. Shared rules live in `src/index.css` (`@import "tailwindcss";`); inline styles are used for runtime dimensions, coordinates, scaling and other dynamic values.
* **SQL Directives**: Any modifications to report exporting must preserve backwards compatibility with `@sheet`, `@totals`, `@split`, `@group`, `@file`, `@protect`, and `@excel_save`.

### Build Commands

#### 1. Web / Full-Stack Output
```bash
npm run build
```
Builds only the client SPA assets (including local DuckDB-WASM files) into `dist/`. To preview the static client, run `npm run preview`; this does not start the Express API.

The Express server is built separately by `npm run build:server` into `build/server.cjs`. `npm run start` rebuilds that server and runs it; it does not build the client or set `NODE_ENV`.

To serve an existing client build with the local Express API, set the environment explicitly:
```bash
# POSIX shell; first run npm run build
NODE_ENV=production npm run start
```
```powershell
# PowerShell; first run npm run build
$env:NODE_ENV = 'production'
npm run start
```
Here “production” selects static assets instead of Vite middleware; it does not add authentication. The server binds to `0.0.0.0:3000` with open CORS and is intended only for a trusted local environment.

#### 2. Desktop Output (Tauri Native)
```bash
npm run tauri build
```
Built binaries (.dmg / .exe / .AppImage) are output to `src-tauri/target/release/bundle/`.

#### 3. Android Output (Capacitor)
```bash
npm run build

# Initial Android platform creation (if android folder does not exist yet):
npx cap add android

# Sync web assets and open project in Android Studio:
npx cap sync android
npx cap open android
```

### Release Build (CI)
The release is built by GitHub Actions (`.github/workflows/build.yml`), which is started **manually** (Actions → *Build Applications (Desktop & Android)* → *Run workflow*).
1. Set the same version in `package.json`, `src-tauri/tauri.conf.json` and `src-tauri/Cargo.toml` (CI takes the release tag `v<version>` from `tauri.conf.json`).
2. Run `npm run lint` and `npm test` locally. On every push the `Tests` workflow (`.github/workflows/test.yml`: type check, Vitest, analysis unit tests and SQL replay) runs; the release build calls it first and does not start unless it passes. Targeted Rust analysis tests run separately in `Analysis native Arrow`; the full Rust suite is not part of the release gate.
3. Start the workflow. After the tests, two jobs run: desktop builds (Windows `windows-latest`, macOS `macos-latest`, Linux `ubuntu-22.04`) and the Android APK (`assembleDebug`, i.e. a debug-signed APK).
4. The result is a **draft** release on GitHub with the installers and the APK; review and publish it manually.
5. CI deletes `package-lock.json` / `bun.lock` and runs `npm install`, so dependency versions are resolved anew on every build.
6. Application identifiers differ on purpose: `com.sqlflow.visualizer` (Tauri) and `com.sqlvisualizer.app` (Capacitor). Do not change them: users' data is tied to them.

* **Исследование**: `npm run test:analysis` запускает проверки node:test; `npm run test:analysis-sql` сравнивает скрипты воспроизведения с живыми View DuckDB-WASM, включая группировки, разрезы, выражения и значимые пробелы. Workflow `Tests` запускает оба набора вместе с Vitest. `Analysis native Arrow` (`.github/workflows/analysis-native.yml`) выполняет `cargo test --manifest-path src-tauri/Cargo.toml --no-default-features analysis::tests -- --nocapture` и `tests/analysisNativeArrow.mjs`, сравнивая нативный IPC с WASM-эталоном. `Analysis export compatibility` (`.github/workflows/analysis-export.yml`) проверяет кодеки/файлы, декодирование PyArrow, восстановление HTML Datagrid и PNG графиков через Playwright; оформление, SQL-диалог и прокрутка в этот экспортный прогон не входят. Это не заменяет ручную проверку интерфейса и сохранения в Tauri/Android; приёмка исследования на Android пока не подтверждена.

* **Подготовка Perspective**: `npm run build:analysis-export` копирует ленивый ассет ZSTD-WASM и применяет два идемпотентных патча для Perspective 5.8.0: `scripts/patch-perspective-duckdb.mjs` сохраняет значимые пробелы в литералах/именах SQL, `scripts/patch-perspective-number-locale.mjs` задаёт числовую локаль Lens и передаёт её значение в worker графиков. Неизвестные версии/шаблоны останавливают подготовку. Команда включена в npm-хуки запуска, сборки и тестов анализа; Vite также готовит локаль при старте и исключает `column-format` из предварительной сборки зависимостей. После замены исходников перезапустите dev-процесс. При обновлении SDK перепроверяйте патчи, пути дат, диапазоны метрик, bootstrap HTML и совместимость JS/Rust Arrow IPC.

* **Точность данных**: При изменениях адаптеров или форматтеров графиков проверяйте точность отображения BIGINT/DECIMAL; сжатие Arrow IPC должно сохранять схему и точные значения.

* **Область HTML-экспорта**: `htmlReplay.ts` регистрирует встроенную таблицу под сохранённым именем и последовательно выполняет load/restore штатного документа Datagrid. Неизвестный шаблон SDK отклоняется явно. Самостоятельный HTML требует интернет для CDN runtime, использует локаль среды открытия и не является архивом всей рабочей области. Восстановление сложного вида, выражений DuckDB и агрегатов нужно проверять на встроенном движке Perspective. HTML-графики через `file://` не входят в подтверждённую поддержку; для графиков используйте PNG. Регрессионный тест локали запускает реальный Blob worker в отдельном JS-контексте без GPU; отрисовку и PNG проверяет браузерный CI.

* **Перед сборкой**: `npm run lint`, `npm test`, `npm run build`.

### Правила и соглашения по коду

* **Локализация (i18n)**: Любой новый пользовательский текст должен добавляться в словарь `src/utils/i18n.ts` одновременно для русской (`ru`) и английской (`en`) версий.
* **Безопасность**: Запрещено жестко прописывать учетные данные или токены в коде. Используйте шифрованный Vault или переменные окружения.
* **Стилизация**: Статическое оформление задаётся утилитными классами Tailwind CSS. Общие правила находятся в `src/index.css` (`@import "tailwindcss";`); инлайн-стили используются для вычисляемых размеров, координат, масштаба и других динамических значений.
* **Директивы SQL**: Любые правки движка отчетов должны сохранять обратную совместимость с директивами `@sheet`, `@totals`, `@split`, `@group`, `@file`, `@protect`, `@excel_save`.

### Сборка релиза (CI)
Релиз собирает GitHub Actions (`.github/workflows/build.yml`), запуск **вручную** (Actions → *Build Applications (Desktop & Android)* → *Run workflow*).
1. Укажите одинаковую версию в `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml` (тег релиза `v<версия>` CI берёт из `tauri.conf.json`).
2. Запустите локально `npm run lint` и `npm test`. На каждый push работает workflow `Tests` (`.github/workflows/test.yml`: типы, Vitest, unit-тесты анализа и SQL replay); сборка релиза вызывает его первым и не стартует, если он не прошёл. Целевые тесты Rust для анализа запускаются отдельно в `Analysis native Arrow`; полный набор Rust не входит в проверку перед сборкой релиза.
3. Запустите workflow. После тестов выполняются две задачи: десктопные сборки (Windows `windows-latest`, macOS `macos-latest`, Linux `ubuntu-22.04`) и Android APK (`assembleDebug`, то есть APK с отладочной подписью).
4. Результат — **черновик** релиза на GitHub с установщиками и APK; проверьте и опубликуйте его вручную.
5. CI удаляет `package-lock.json` / `bun.lock` и выполняет `npm install`, поэтому версии зависимостей определяются заново при каждой сборке.
6. Идентификаторы приложений разные намеренно: `com.sqlflow.visualizer` (Tauri) и `com.sqlvisualizer.app` (Capacitor). Менять их нельзя: с ними связаны данные пользователей.

# Исследование данных с Perspective (экспериментально)

В контекстном меню физической таблицы DuckDB выберите **Исследовать**.
Perspective откроется на всю рабочую область: группировки, фильтры, агрегаты,
вычисления, таблицы и графики настраиваются штатными средствами Viewer.
Поддерживается текущее подключение Desktop/Tauri или WASM (Web/Android).
Express/DuckDB и ClickHouse как источники этого режима пока не поддерживаются.
Произвольный SQL, VIEW и TEMP-таблицы напрямую не открываются: подготовьте
физическую таблицу обычным SQL редактора.

## Навигация и состояние

- **В редактор** скрывает Viewer, сохраняя исследование в памяти. В редакторе
  появляется строка **Продолжить исследование** и **Закрыть исследование**.
  Повторное действие «Исследовать» для той же таблицы также возвращает Viewer.
- **Закрыть исследование** освобождает Viewer, его клиенты и временные объекты
  через API Perspective. Исходная таблица и общее соединение остаются.
- Открытие другой таблицы заменяет текущее исследование. Переподключение, в том
  числе к тому же файлу, завершает его до замены соединения.
- **Обновить** перечитывает источник и восстанавливает рабочую область Viewer
  в памяти, включая панели. После изменения таблицы в редакторе обновите исследование.
  Если схема стала несовместимой с конфигурацией, закройте его и откройте заново.
- Постоянного автосохранения нет. Перезапуск начинает чистую песочницу;
  для сохранения используйте экспорт Viewer. Android «Назад» возвращает в редактор.

Верхняя строка содержит источник, количество исходных строк и строк активного
представления (включая итоги/раскрытые группы), обновление, SQL и статус.
Код и WASM Perspective загружаются лениво при первом открытии. Закрытие освобождает
ресурсы исследования; загруженные модули остаются в кэше страницы, а общий DuckDB
продолжает обслуживать редактор.

## Воспроизводимый SQL

Откройте нужную панель/график и нажмите **SQL представления → Копировать SQL**.
Вставьте весь скрипт в редактор Lens на той же базе и выполните обычной командой.
Редактор автоматически не изменяется. Скрипт строится по операциям адаптера для
активного View: необходимые временные таблицы, изменения раскрытия групп и
финальный SELECT всего представления. Показ SQL не выгружает весь набор данных.
Служебные имена изолированы от работающего Viewer, повторный запуск того же
скрипта заменяет только его собственные временные таблицы.

SQL воспроизводит разрез и метрики, включая данные графика; оформление, тип графика
и подписи осей задаются Viewer. Служебные поля дерева групп могут присутствовать
в результате. Исходная таблица должна оставаться доступной и неизменной для
повторения тех же значений. Обычный лимит выдачи редактора 500 000 строк сохраняется.
После выполнения SQL остаются отдельные временные таблицы `lens_replay_*`.
Команды удаления указаны в конце как комментарии: выполняйте их отдельно после
работы с результатом. Они не относятся к объектам открытого исследования.

## Архитектура и ограничения

Один экземпляр и одно соединение DuckDB используются редактором и Virtual Server.
Источник заранее целиком в JS не копируется. Perspective запрашивает вычисленные
окна/результаты через DuckDBHandler. Native-транспорт передаёт Arrow IPC через
Tauri, максимум 100 000 строк и 32 MiB на один ответ; это лимит ответа, не источника.
Он не меняет SET-параметры соединения. Подключение сохраняет существующие настройки
совместимости Arrow. Размеры данных для графиков зависят от конфигурации.

- BIGINT/DECIMAL в Perspective могут терять точность; корректность IPC не гарантирует
  точность вычислений/форматирования в Viewer. Сопоставляйте важные метрики с SQL.
- Штатные элементы Perspective — на английском; элементы Lens — RU/EN.
- CSV/JSON/NDJSON/Arrow экспортируются постранично, но файл собирается в памяти JS.
  HTML включает **все исходные физические таблицы рабочей области**, все панели,
  раскладку, глобальные фильтры, роли master/detail и определения производных таблиц.
  Внутри находятся Perspective, стили, DuckDB-WASM и workers: сеть и Lens для
  открытия не требуются. Физические источники читаются напрямую как Arrow до
  преобразования типов Perspective. В полученном файле используется тот же
  DuckDBHandler, включая SQL-выражения; активной панели достаточно для выбора
  пункта HTML, экспортируется вся рабочая область. HTML можно повторно экспортировать.
  Современный браузер должен поддерживать WASM, Web Workers и DecompressionStream.
  Служебная часть HTML занимает около 21 МБ плюс данные; расход памяти зависит
  от ширины/объёма источников. Функции и расширения нативной DuckDB, отсутствующие
  в включённой WASM-версии, автоматически не переносятся.
- LZ4/ZSTD реализованы как сжатие физических буферов Arrow IPC для текущего
  представления, всего источника и выделения. Значения и схема не пересчитываются.
  Результат проверяется независимым PyArrow. «Все функции Viewer проверены» пока
  не заявляется; поведение отдельных функций зависит от DuckDB Virtual Server.
- Используются внутренние API pinned Perspective 5.8.0 и совместимость заголовков
  дат. Обновлять SDK без проверки адаптера, SQL и экспорта нельзя.
- Скачивания в Web не подтверждают поведение файлового экспорта Android/Desktop.

## Установка и проверки

Используйте Node.js 22+ и `npm ci`. `.npmrc` сохраняет существующий prerelease
DuckDB-WASM при несовпадающем peer-диапазоне Perspective. Добавлен явный `react-is`
19.3.1 — peer существующего Recharts, который пропускается в этом режиме установки.
Perspective client/server/viewer/datagrid/charts закреплены на 5.8.0; JS Arrow — 17.0.0.
Rust `arrow-ipc` 58 использует ту же семью Arrow, что закреплённый duckdb-rs
1.10505.0. Для Arrow IPC добавлены lz4js 0.2.0 и @bokuweb/zstd-wasm 0.0.27;
flatbuffers 24.12.23 стал явной зависимостью без смены уже установленной версии.
Кодеки загружаются по требованию. Версии существующих зависимостей не обновлены.
`predev`, `prestart`, `prebuild` и `pretest:analysis` собирают автономный runtime
из установленных пакетов; сгенерированные файлы public/analysis-* не коммитятся.
Сам Lens скачивает runtime только при HTML-экспорте, ZSTD WASM — при ZSTD-экспорте.

Базовые команды: `npm run lint`, `npm run test:analysis`, `npm run test:analysis-sql`,
`npm run build` (обычная Web-сборка). Существующий `npm test` остаётся отдельно.
Тесты SQL сравнивают фильтр/average/count с контрольным SQL, воспроизводят скрипты
дважды в общем соединении, проверяют даты, split, раскрытие и 730 колонок.

Workflow **Analysis native Arrow** запускается на соответствующих push/PR и вручную.
Без релизной сборки он компилирует Tauri, проверяет native-транспорт, лимиты, DDL,
пустую выдачу и типы; выполняет SQL pinned SDK путём подготовки скрипта как в редакторе;
затем JS Arrow 17 читает настоящие Rust IPC-файлы и сравнивает результаты с WASM.
Зелёный CI подтверждает этот путь, но не заменяет ручной запуск Tauri и Android.

Workflow **Analysis export compatibility** дополнительно проверяет сжатые IPC
через PyArrow и открывает HTML как file:// в новом браузерном контексте с отключённой
сетью: две панели, SQL-выражение, раскладка, фильтры и метрики должны совпасть.
Наличие workflow не означает, что он уже выполнялся; результаты первого запуска
следует проверить до приёмки автономного HTML. Исходники npm-компонента не меняются:
перехват меню ограничен конкретным Viewer, а вызовы PNG/конфигурации делегируются SDK.

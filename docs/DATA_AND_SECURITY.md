# Данные и безопасность

Где приложение хранит данные, что передаёт по сети и какую защиту даёт Vault. English version: [DATA_AND_SECURITY_EN.md](./DATA_AND_SECURITY_EN.md).

## 1. Где что хранится

Все данные хранятся локально, в профиле браузера или WebView (десктоп и Android) без шифрования, кроме содержимого Vault.

### localStorage

| Ключ | Содержимое |
| :--- | :--- |
| `sql_visualizer_session_v2` | Состояние интерфейса: активная вкладка, направление графа, тема, путь к открытой базе DuckDB, параметры подключения ClickHouse **без пароля**, состояние панели схемы. Поле `tabs` в этой записи — остаток старых версий и не пишется: тексты вкладок лежат в `sql_visualizer_tabs_session` |
| `sql_visualizer_tabs_session` | Тексты вкладок (SQL, имя файла, признак изменений). При переполнении localStorage тексты уходят в IndexedDB `sql_visualizer_tabs_db` |
| `sql_visualizer_ui_visibility_v1` | Настройки интерфейса и движков: размеры страницы, масштаб, параметры DuckDB (память, каталоги, потоки), **Init SQL**, путь синхронизации |
| `sql_visualizer_hotkeys_v1`, `sql_visualizer_formatter_v1` | Горячие клавиши, правила форматирования |
| `sql_quick_action_templates`, `sql_custom_autocomplete_templates` | Быстрые действия, шаблоны автодополнения |
| `queryast_lens_excel_settings_v1`, `queryast_lens_excel_presets_v1` | Настройки и пресеты Excel |
| `sql_custom_snippets_v2`, `sql_custom_snippets_v2_migrated`, `sql_favorite_snippets_ids_v1`, `sql_deleted_snippets_ids_v1` | Старая локальная копия сниппетов (после переноса в IndexedDB удаляется) и отметка о переносе, избранное, удалённые |
| `app_lang` | Язык интерфейса |
| `sql_last_workspace_sync_time` | Время последней синхронизации рабочего пространства |
| `sessionStorage`: `sql_is_importing_session` | Служебный флаг на время импорта |

### IndexedDB

| База | Содержимое | Ограничения |
| :--- | :--- | :--- |
| `sql_visualizer_results` | Последний результат запроса каждой вкладки (строки таблицы) | Удаляется для закрытых вкладок |
| `SQL_VersionHistory_DB` | История версий SQL (автосохранение и ручные снимки) | До 500 автоматических и 300 ручных версий |
| `SQL_Snippets_DB` | Библиотека сниппетов | — |
| `sql_visualizer_schema_cache` | Кэш схемы БД | Записи старше 7 дней очищаются |
| `sql_visualizer_tabs_db` | Запасное хранилище вкладок | Используется при переполнении localStorage и для миграции |
| `app_secure_vault_db` | Зашифрованные секреты Vault | Не входит в экспорт и синхронизацию |

### Файлы (десктоп)

* Файл синхронизации рабочего пространства: путь из настроек; если указана папка — `sql_visualizer_workspace_sync.json` в ней. На десктопе файл записывается через временный файл `*.tmp` в той же папке с последующим переименованием, поэтому оборванная запись (закрытие окна, нехватка места) оставляет прежний файл целым; одновременные сохранения сессии выполняются по очереди.
* SQL-файлы, сохранённые пользователем; Excel-отчёты (в том числе по `@excel_save`); шаблоны Excel читаются по пути из `@template` / `@template_values` (только чтение); экспорт ClickHouse `COPY TO`.
* Базы и временные файлы DuckDB: файл `.duckdb`, каталоги `temp_directory` и `extension_directory` из настроек.

## 2. Что попадает в экспорт и синхронизацию рабочего пространства

Файл синхронизации и ручной экспорт («Экспорт» в настройках) содержат:
* все ключи localStorage, **кроме** ключей, в имени которых есть `vault` или `secret`, и служебных `sql_last_workspace_sync_time`, `sql_is_importing_session`;
* до 500 версий истории и сниппеты из IndexedDB.

Не попадают: содержимое Vault (хранится в IndexedDB, не в localStorage), пароль ClickHouse (не сохраняется вообще), результаты запросов и кэш схем.

Следствия:
* **Init SQL и сниппеты экспортируются открытым текстом.** Не записывайте в них пароли, ключи доступа и токены (например, `CREATE SECRET … KEY_ID/SECRET`). Подстановка `{{ИМЯ}}` из Vault для Init SQL не выполняется.
* При импорте сохраняются локальные параметры DuckDB с нестандартными значениями: память (кроме `8GB`), временный каталог (кроме `./tmp`), каталог расширений (кроме `./extensions`), потоки (кроме `0`) и непустой Init SQL. Сохраняются также непустые пути синхронизации и корня дерева файлов, а масштаб интерфейса — если задан. Значения DuckDB по умолчанию могут быть заменены импортируемыми.
* Побеждает более новый файл; подробности — в [руководстве](./USER_GUIDE.md#автосинхронизация-рабочего-пространства-workspace-sync-path).
* Файл синхронизации лежит в папке, которую вы выбрали (например, в облаке). Защита этой папки — на вашей стороне.

### Порядок импорта и сохранения

* Ручной импорт проверяет оболочку пакета (`app`, числовую `version`, объект `data`), очищает localStorage и последовательно применяет данные. Проверка `app` ищет текст `workspace bundle`, а версия проверяется на конечное число; строгой проверки поддерживаемых версий и содержимого всех полей нет.
* Автоимпорт при запуске проверяет наличие `data` и `exportedAt`, сравнивает время файла с последней синхронизацией и применяет данные без предварительного очищения localStorage. Оба пути используют `applyWorkspaceBundleSilently`.
* Импорт не является общей транзакцией между localStorage и базами IndexedDB; автоматического отката при ошибке нет. Временный файл защищает запись файла синхронизации, а не применение импорта.
* Сессия сохраняется при скрытии страницы, уходе Android в фон, закрытии окна и раз в 10 минут. На закрытие Tauri отводится до 2 секунд ожидания асинхронного сохранения. Ошибки `saveSessionTabs` записываются в консоль и не отклоняют возвращаемый Promise.

## 3. Vault (хранилище секретов)

* Алгоритмы: PBKDF2-SHA256 (100 000 итераций) для получения ключа из PIN, шифрование AES-256-GCM (Web Crypto API). Все секреты шифруются одним массивом в записи `root_vault`; при каждом шифровании генерируются новые случайные соль (16 байт) и вектор инициализации (12 байт). Ключ не экспортируется.
* PIN: только цифры, не короче 4. Без PIN данные не расшифровать, **восстановить PIN нельзя** (можно только сбросить хранилище вместе с секретами).
* Разблокировка действует 12 часов после ввода PIN. Истечение срока проверяется при следующем обращении к состоянию Vault (`isVaultUnlocked`); тогда состояние в памяти очищается и доступ блокируется. Отдельного таймера очистки, настройки срока и таймера неактивности нет. Закрытие приложения тоже блокирует хранилище. Заблокировать вручную можно кнопкой в разделе Vault.
* Использование: `{{ИМЯ}}` в SQL заменяется значением непосредственно перед выполнением; в вкладке, истории версий и сниппетах остаётся текст с `{{ИМЯ}}`. Допустимые символы имени: латинские буквы, цифры, `_`, `-`. Секреты с префиксом `ch_` — строки подключения ClickHouse, они предлагаются списком в форме подключения.
* Если в SQL есть `{{`, а хранилище заблокировано (или не настроено), запрос не выполняется — в том числе когда секретов в запросе нет.

**Что Vault не защищает:**
* 4–6-значный PIN может быть подобран перебором, если злоумышленник получил файл базы IndexedDB: число вариантов мало. Используйте длинный PIN.
* Пока хранилище разблокировано, секреты и введённый PIN находятся в памяти приложения. Истечение срока само по себе не запускает очистку: она выполняется при следующей проверке состояния Vault.
* После подстановки значение секрета входит в текст запроса, который уходит в базу: он может попасть в журналы сервера (например, `system.query_log` ClickHouse), а текст ошибки базы может содержать фрагмент запроса.
* Init SQL, сниппеты, история версий и результаты запросов не шифруются.

## 4. Сеть

* Основные сетевые обращения: ClickHouse (по `http://` или `https://`; пароль передаётся в заголовке `X-ClickHouse-Key`, при `http://` — открытым текстом) и источники данных, к которым обращаются ваши SQL-запросы (`read_parquet('https://…')`, `httpfs`). В собственном коде приложения вызовов аналитики и телеметрии нет.
* В режиме разработки запросы идут на локальный сервер Express (`server.ts`, слушает `0.0.0.0:3000`, CORS открыт для всех). Он предназначен только для разработки на вашей машине и не должен публиковаться в сети (авторизации нет).
* DuckDB-WASM обычно загружается из локальных файлов `public/duckdb`, копируемых при запуске и сборке. Если выбор локального bundle завершается ошибкой, код пробует bundle с CDN jsDelivr. Установка и автозагрузка расширений DuckDB также могут обращаться к репозиториям расширений.
* Android: `cleartext: true` в `capacitor.config.json` разрешает HTTP-подключения (нужно для ClickHouse без TLS).

## 5. Права десктопного приложения (Tauri)

Конфигурация `src-tauri/tauri.conf.json` выдаёт окну широкие права: `allowlist.all`, чтение и запись файлов по всему диску (`fs`-область `$HOME/**`, `/**`, `C:/**`…`F:/**`), HTTP на любые адреса, политика безопасности контента (`csp`) не задана. Команды Rust `read_text_file` и `write_text_file` принимают любой путь. Команда `list_dir` отдаёт содержимое любой папки (для дерева файлов), а `open_path` запускает внешней программой только файлы с расширениями из белого списка (Office, PDF). Команды контекстного меню дерева принимают любой путь: `rename_path` (переименование в пределах папки, существующий файл не перезаписывается), `move_path` (перенос в другую папку того же диска, существующая запись не перезаписывается), `trash_path` (перемещение в корзину ОС, не удаление), `reveal_path` (показать в проводнике) и `open_with` (системный выбор программы). Сужение прав и включение CSP на данный момент не выполнены. Практический смысл: код, выполняющийся в интерфейсе, имеет доступ к файлам пользователя, поэтому интерфейс защищён на уровне содержимого — Markdown и подписи графа очищаются через DOMPurify, подсветка SQL экранирует текст, «сырой» HTML не исполняется.
